# MineralForge: Blast Vibration Risk Predictor

## 1. Purpose

1.1. MineralForge is a focused mining geotechnical MVP for **blast vibration risk prediction**.

1.2. The input is a blast vibration record with charge weight, burden, spacing, PPV, frequency, and soil or rock type.

1.3. The output is a `Low`, `Medium`, or `High` blast vibration risk class, estimated PPV, probabilities, feature explanations, and a field-review recommendation.

1.4. The included dataset is used for demonstration and model development. This repository does not claim real mine validation or production safety certification.

## 2. Use Case

2.1. A field engineer or monitoring device provides blast vibration data.

2.2. The pipeline engineers geotechnical features such as effective distance, scaled distance, estimated PPV, acceleration resultant, and PPV-frequency product.

2.3. The trained model predicts vibration risk.

2.4. A CrewAI multi-agent workflow frames the review process:

1. Blast Data QA Agent validates the blast vibration input.
2. Vibration Risk Model Agent scores the event with the trained model.
3. Geotechnical TARP Agent converts the risk class into a field recommendation.

## 4. Train The Model

4.1. Train with the default GridSearchCV tuner:

```powershell
python train_pipeline.py --tuner grid
```

4.2. Train with Optuna when the optional dependency is installed:

```powershell
python train_pipeline.py --tuner optuna --optuna-trials 40
```

4.3. Training compares Random Forest, Logistic Regression, and optional XGBoost.

4.4. Training records macro F1, high-risk recall, confusion matrix, best parameters, feature importance, and a model card.

## 5. Generate Predictions

5.1. Score the included dataset:

```powershell
python predict.py --input data\ground_vibration_dataset.csv --output artifacts\predictions.csv
```

5.2. The prediction output includes `Predicted_Vibration_Level`, estimated PPV where available, class probabilities, and `TARP_Recommendation`.

## 6. Run The CrewAI Workflow

6.1. The CrewAI workflow is implemented in `src/mineralforge/agents/crew.py`.

6.2. It keeps model inference deterministic while giving the MVP a clear multi-agent review chain for data QA, model scoring, and geotechnical action review.

6.3. CrewAI is optional at runtime. If it is unavailable, the same deterministic workflow still scores the CSV and produces recommendations.

## 7. Launch The Dashboard

```powershell
streamlit run dashboard.py
```

7.1. The dashboard shows high and medium risk counts, average PPV, PPV timeline, PPV-frequency scatter, feature importance, and scored blast events.

## 8. Run The API

```powershell
uvicorn api:app --reload
```

8.1. The API exposes `/health` and `/predict` for blast vibration inference.

8.2. The `/predict` endpoint accepts charge weight, burden, spacing, PPV, frequency, delay, and soil type.

## 9. Visualize The Dataset

```powershell
python visualize_dataset.py
```

9.1. The visualization script creates class balance, sensor trends, feature distributions, PPV-frequency scatter, correlation heatmap, and soil-type charts.

## 10. Model Outputs

10.1. `artifacts/vibration_detection_pipeline.joblib` stores the trained model pipeline.

10.2. `artifacts/metrics.json` stores accuracy, macro F1, high-risk recall, confusion matrix, and tuning metadata.

10.3. `artifacts/feature_importance.csv` stores model feature importance when supported.

10.4. `artifacts/shap_summary.csv` stores mean absolute SHAP values when SHAP supports the selected model.

10.5. `artifacts/MODEL_CARD.md` explains intended use, validation status, metrics, and limitations.

## 11. Limitations

11.1. The included data is suitable for demonstration and engineering workflow development.

11.2. The model must be calibrated and validated with site-specific blast monitoring data before any operational safety use.

11.3. The TARP recommendation is a decision-support output, not a replacement for a competent geotechnical engineer.
